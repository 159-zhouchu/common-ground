# 共桌本地源码全面复核记录

日期：2026-10-25。对象：正式目录 `共桌CommonGround`，以源码和本轮实测为依据。第三方评分和测试汇总仅作线索，不作为本轮通过证据。此次未发布到 GitHub，未调用真实付费模型。

## 确认的问题与修正

| 问题 | 原因与结果 | 修正与验证 |
| --- | --- | --- |
| JSON 非对象输入触发内部错误 | `settings` 等接口在解析 JSON 后直接访问属性，`null` 导致 500。修复前隔离生产 HTTP 实测得到 `500 !== 400`。 | 先验证请求是 JSON 对象；针对 settings、连接保存/删除、文稿保存和讨论测试 null、数组、布尔、数字、字符串共 25 种组合，均为 400，连接与工作区完全不变。 |
| 供应商响应总量没有上限 | 9 KB 限制只约束解析后的模型结果，原先 `response.json()` 会先完整接收供应商信封及附加字段。 | 在 JSON 解析前按实际读取字节限制整个解压后响应为 1 MiB，超限取消读取，返回 `PROVIDER_RESPONSE_TOO_LARGE` / 502；不重试，不透传供应商原文，费用保留未知。9 KB 结果限额继续有效。 |
| 畸形供应商信封错误不明确 | null、错误的 output/content 类型可能触发属性或数组操作异常。 | 校验 Responses / Chat 信封的必要结构，将畸形 JSON 和结构错误统一转为安全的 `INVALID_OUTPUT` / 502，保留正常协议与截断错误的原有行为。未知元数据仍允许。 |
| 讨论重放被当前连接状态阻断 | API 在运行器检查幂等键前判断连接是否可用；原连接停用/删除后无法取得已有运行。 | 使用稳定连接 ID，由运行器先验证原请求指纹，再验证新调用的连接可用性。旧 slot 请求重放使用原记录中的角色映射；新请求仍不回退其他模型。同键换接收方返回 409。 |
| 协作轮询可能重叠 | `setInterval` 与列表/详情异步读取并行，同一轮生命周期内旧请求可能晚到并覆盖新状态。 | 改为本次列表与详情读取结束后再安排下一次轮询；选中记录改变、状态改变或卸载时取消旧周期。 |

供应商边界新增 6 项测试：Responses/Chat 正常与恰好 1 MiB 的响应、无长度分块超限并取消、过大/虚报长度、畸形结构与错误脱敏、失败后正常调用。HTTP 另经真实本机模拟服务验证超大信封被拒绝、后续请求成功，以及停用/删除后同键重放零额外调用。

修复前新增的供应商分块测试因旧实现等待无结束流而被人工中止，日志仅作诊断，不计为已完成的修复前测试。最终回归均正常结束。

## 清理与保留

- 删除无引用的 `.cg-connection-choice` 样式。
- 删除连接抽屉两处已无法匹配的 `h1` 字号规则；抽屉现有 `h2` 规则保留，浏览器确认页面仍只有一个 h1。
- 未发现当前 `ambient.tsx`、grain 资源、`ag-header` 或 `data-reveal` 残留；没有再次删除不存在的文件。
- 保留官方 CLI/MCP、旧连接迁移、幂等/版本兼容、JSON 原子事务、DOCX Worker 与其容量保护。它们有实际调用或兼容职责，不能因不在首屏出现就删掉。
- 未删除用户评审材料、`_check` / `_check2`、设计参考、宣传视频及验收证据。

## 对最新三项建议的取舍

1. **Worker 工作目录**：保留官方项目根目录启动契约，README 已要求从项目根运行，Worker 注释明确路径前提。未宣称支持任意服务管理器工作目录；不直接改为会受 Next 打包影响的源模块相对 URL。此项是已公开前提，不是本轮已消除的限制。
2. **JSON 存储成本**：保留同步事务与原子替换，避免为优化速度引入异步落盘和状态一致性变化。纳秒文件指纹缓存继续生效，但全量克隆、序列化、无界历史增长仍是限制。尚无长历史压力测试证明应迁移 SQLite。
3. **局部结论失效**：保持版本改变后待复核。即使目标段落未改，其他段落也可能改变其含义或约束；没有明确依赖模型前不自动延用“通过”。精细提示属于后续产品优化。
