# 启动与可维护性复核 · 2026-10-23

本次逐项核对用户转交的 Gemini 五项建议。第三方描述作为排查线索，结论以当前源码与隔离测试为准。

## 核实与处理

1. **Node 版本未预检：成立，已修复。** `scripts/check-node.mjs` 统一比较最低版本 22.9.0；Windows 双击脚本在 `npm ci` / 构建前执行，`scripts/start.mjs` 也导入检查。不支持时显示当前与最低版本并退出，尚未创建数据目录、下载依赖或启动服务。版本判断按数值逐段比较，不用字符串大小或仅看主版本。

2. **崩溃遗留空锁阻塞启动：成立，已修复。** 锁处理移入 `scripts/launcher-lock.mjs`。不完整记录保留 5 秒写入宽限，旧空锁/损坏记录可回收；有效 PID 对应的启动器仍存活时拒绝抢占。回收前复查文件状态，释放时核对本次随机 token，避免旧命令清理已被替换的记录。原并发启动、端口与实例识别检查保留。

3. **单进程异步回调覆盖：所述触发机制不成立；重复读盘问题成立，已改善。** 同步读文件、反序列化、回调与写文件之间没有 `await`，大文件解析只会阻塞当前线程，不会让另一个异步回调插入。`workspace.json` 与 `agent-jobs.json` 也是不同文件。没有证据把原实现定性为已发生的并发丢更新。

   新增 `lib/json-store.ts`，按绝对路径在进程内共用解析缓存；检查文件大小、标识及纳秒时间戳，未变化时不重复读文件/JSON.parse。查询与事务返回独立副本，事务在副本上同步修改，拒绝 Promise 与嵌套写事务。原子写入成功后才更新缓存，写盘失败不污染已提交状态。文件外部变化时重新读取；这不代表支持多个服务进程同时写入。

   **未采用异步节流落盘。** 保留“写盘成功才确认操作”的行为。完整 JSON 序列化、同步原子写盘与副本复制仍存在；没有声称解决大历史数据的全部性能问题，也未做本轮大型历史性能基准测试。数据库/增量写入应作为独立改造。

4. **讨论提问重复落盘：不成立，补充注释与验证。** `getTask` 返回独立快照：当前提问加入该快照用于预检与推理；成功取得可用结果后，再向最新持久化任务追加一对问答。两个对象不同。新增 S0 自检、S1、S5 多步讨论测试，逐步验证每个模型输入只含一条本次提问，最终历史也只有一条用户提问与一条回复。原有失败、取消和校验失败不留下孤立提问的检查保留。

5. **压缩排版与超大组件：成立，已整理。** 引入锁定版本的 Prettier，配置 `format` / `format:check`；对 app、lib、scripts、tests 的 TS/TSX/MJS 恢复标准多行排版。Next 自动生成的 `next-env.d.ts` 排除，避免构建后格式检查反复冲突。

   `app/workbench/` 拆出 `MaterialsDrawer`、`VersionsDrawer`、`DiscussionDrawer` 和 Sheet / SourceText / Diff 等共用组件，并清理相应无用导入。主组件继续管理项目、请求、草稿和主栏；没有声称已完成全部 Hook、CheckBar、DocumentEditor、FindingsPanel 的拆分。文件夹用途说明已补充。
