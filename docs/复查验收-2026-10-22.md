# 共桌复查与修正 · 2026-10-22

本次根据用户提供的豆包检查报告，复查启动停止、重复提交、数据与版本、项目和协作管理、页面导航及交付包。第三方报告作为线索，以下区分源码确认与本机实测。旧验收资料只代表当时的版本和平台。

## 修正

- 删除停止脚本中按 Next 路径、端口字符串和 `/proc` 命令行判断身份的实现。Next 可以改写进程标题，macOS 也没有 `/proc`；原实现不能作为跨平台停止依据。
- 启动时生成独立的 256 位停止凭据，保存到本机 owner 文件并传入服务进程。停止请求同时核对实例、PID 和凭据，由对应服务向自身发送 SIGTERM，走 Next 的退出处理。凭据不回传健康或配置接口；接口拒绝跨站、缺少凭据及错误身份。
- 等待进程退出且端口关闭后才报告成功和清理记录；请求失败或超时保留记录并返回失败。兼容 owner 存在但 PID 文件丢失。旧版无凭据实例明确拒绝，升级前须先关闭旧服务。
- 启动器增加互斥，防止同时启动覆盖 owner；同端口来自另一数据目录的服务明确拒绝，避免操作错误工作区。POSIX 仅用 `ps stat` 识别已终止的僵尸进程，不依赖进程标题，也不按查询结果终止无关 PID。
- 文稿检查和讨论在响应丢失后的相同提交中保留请求编号。收到成功响应后释放编号；任务版本、目标接收者或输入改变时生成新编号。避免服务端已收单、浏览器重试又创建付费任务。
- 清理 API 未使用导入、页面未使用变量、测试未使用导入；删除只做转导出的 `app/workbench.tsx`，首页直接引用实际组件；删除未使用的旧品牌 CSS 和始终隐藏的调用柱条 JSX/CSS。启用 TypeScript 的 noUnusedLocals / noUnusedParameters。

继续保留前序结果容量预留、输入/输出上限、隔离调用、取消及迟到结果保护、原子写盘重试、版本冲突检查、历史与回收恢复。没有为凑清理数量删除有效功能或历史数据。
