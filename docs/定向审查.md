# 定向审查与分项验收（本地修改）

文稿审阅页新增“审查范围与验收”。选择整篇、选中段落或指定问题，填写 1–6 个审查项与验收标准；勾选“本次”的项目才会提交。每次仍按选定的 S0/S1/S5 策略调度，不因审查项增多而逐项增加请求。

完整方案、参考材料和最近讨论仍作为上下文发送；选择段落并不减少共享数据或绕过输入大小限制。段落审查的修改只能落在选中段落，越界结果会令该步骤失败。指定问题的主题边界依靠模型理解，服务端不声称已经完成语义验证。

模型分别返回通过、需修改、证据不足，以及理由与原文引用。通过只表示符合本次标准，不是全文正确认证。没有修改建议不等于通过。服务端验证每个验收项完整且不重复；引用必须逐字匹配指定正文或参考材料。模型同时填写两个引用 ID 时，仅保留实际命中的位置；需修改项没有独立引用时，可用同项建议中唯一匹配的范围内原文作为定位依据。通过项不使用补丁兜底；仍无有效依据时降为证据不足。原文可定位不等于修改理由或事实正确，仍需人审。

“准备复查此项”载入原范围和标准，保留其他验收项配置，仅勾选当前复查项；达到六项上限且无法追加时提示用户先调整，不静默删项。确认后再次点击“开始检查”才会调用模型。一次完整成功的复查只更新同一范围、同一标准的对应条目，其他项目保留原结论和版本。失败、取消或部分完成不会覆盖此前完整结论；已完成的步骤及费用保留在调用记录中。不同标准、不同范围和演示／真实运行的记录分别保留。

主面板优先展开当前范围和标准的结论；没有匹配时显示最近一轮，其他范围和旧标准折叠保存。删除段落后自动清理失效 ID，若局部范围为空会要求重新选择，不自动扩大为整篇审查。“审查此段”在未勾选任何验收项时选中现有清单。

真实定向审查的修改建议必须绑定本次需修改的验收项。完整复查成功后，该项旧的未决建议保留在“全部记录”，不再计入待办或需重查；其他项建议及人工采纳／拒绝决定保持原状。引用核验降为证据不足的条目不会附带可直接应用的修改。

结论绑定运行时的正文版本、任务目标和材料版本。正文（含恢复旧稿）、约束或材料发生变化后，旧结论保留并标为待复核；当前实现保守提示所有相关审查记录，不自动判定未引用段落的语义改动“无影响”。修改建议的版本校验仍独立生效。

审查设置按项目暂存在当前浏览器；运行后，实际范围、验收标准和结论保存在本机运行记录中。Markdown / DOCX 勾选审阅记录时包含分项结论与版本。旧数据没有分项结论，不自动追认通过。只看原材料的新分支和普通讨论保持原流程，不产生分项验收结论。

合成示例不调用模型，不会为用户自定义标准伪造通过结论。真实模型的格式兼容性和判断质量需要另行验证。本次验证仅使用隔离临时目录和本机模拟供应商。
