# 代码审查修订与验收 · 2026-10-22

本轮对照 Gemini 的第三方评审核实并修订当前瑞士红白版。以下记录代表实际代码与隔离测试结果。

## 核实与处理

| 问题 | 处理 |
|---|---|
| 多步预检没有为前序结果留空间 | 已确认存在风险，但并非所有 95 KB 任务都必然在第 4 步失败。Agent 初始目标/阶段/上下文最多 70,000 UTF-8 字节；文稿多步请求初始输入最多 80,000 字节。启动前逐步检查初始输入和前序结果预留，超限不创建任务、不发请求。S1 原材料模式也预检最终比较时的当前文稿。 |
| 只降低初始输入仍不能保证后续容量 | 每步接受的完整结构化 JSON 最多 9,000 字节，按每份 9,512 字节预留包装空间。超过上限显式失败，不截断证据或建议，不传给后续步骤。系统提示同步要求精简结果；单步文稿也采用该结果上限。每次请求仍执行 100,000 字节用户输入检查，供应商协议和系统指令另外封装。 |
| 讨论失败残留单边 user 消息 | 新讨论先在内存快照参与推理，成功回复时成对写入正式消息。失败、停止、预检拒绝不新增讨论消息，运行中的提问仍在调用记录中保留。前端收到任务启动响应后不清空输入，成功终态才清空原提问；用户已修改输入时不覆盖。未批量重写历史孤立消息。 |
| 项目与协作记录只增不减 | 项目选择器和“更多”增加项目管理，支持重命名及回收恢复；协作台增加新建空白视图、协作回收站和恢复。项目 50 个、协作 100 条上限只计使用中记录，恢复时重新检查。运行中及已停止但尚未结束的请求阻止回收，避免迟到回调访问被移走的数据。 |
| 第 1 段无法删除 | 编辑时任意段落均可删除，至少保留一段；确认后只改草稿，保存创建新版本，历史原文可恢复。 |
| partial 横幅隐藏失败原因 | 展示首个失败步骤名称与实际错误，包括预算不足等原因。 |
| 废弃视觉代码 | 删除未引用 ambient.tsx 和 grain.png、data-reveal 属性及未使用图标；移除不再影响布局的概览/标题 ResizeObserver，保留菜单定位所需的操作栏高度观察。清理协作页死 header/brand 规则与相同作用域中被后续规则覆盖的属性，保留当前响应式层叠顺序；拆开 product.css 中重复的标签属性。 |
| Windows 原子重命名冲突 | 独立原子写盘模块使用 PID + UUID 临时文件；仅 EPERM/EACCES/EBUSY 最多短重试 3 次（20/40/60 ms），失败保留旧目标并尝试清理临时文件。这不等于跨进程事务锁，仍只支持单进程本机服务。 |
| 分享 ZIP 是 GBK | 未证实，旧 ZIP 的全部 72 个条目均已设置 UTF-8 标志 0x800。打包脚本现显式指定 UTF-8，并保留独立解压/逐文件哈希校验；另排除 desktop.ini。 |

## 新一份清单复核与补修（同日）

用户再次提供的详细清单引用的是修订前源码（如 95,000 字节、固定 .tmp、提前 messages.push、缺少回收站、ambient.tsx）。上述条目现已在当前源码和自动化测试中核实为已修复，不重复改回旧实现。讨论仍采用临时快照供模型读取、成功后成对落盘，较“预检后先保存用户消息”更能避免请求失败/停止留下孤立提问。

本次补齐前后端容量计算口径：新增不依赖 Node API 的 lib/document-input.ts，共用步骤定义、阶段指令、清单字段及容量判断。浏览器计算包含 duty/input 包装、mode/excluded/hash、UTF-8、JSON 转义与最近 10 条消息；SHA-256 使用相同的 64 字节长度。S1 原材料模式逐阶段计算，最终比较显式读取全文。服务端启动前使用相同规则，并继续校验真实连接 URL 与实际请求。显示两位小数及精确字节 title，前序结果预留单列，避免近阈值仍误显示可发送。

## 验证

- 类型检查、生产构建通过。
- 68 项单元/集成测试通过：包含接近 70 KB / 80 KB 的多步输入和接近 9 KB 前序结果、启动前超限拒绝、超大结果停止下游、讨论成功/失败/停止/幂等、50/100 满额回收恢复、部分完成报错、原子写盘短暂/永久错误。新增验证页面容量逐步等于实际用户请求字节、中文/emoji/转义文本、80/100 KB 临界值加 1 字节拒绝、S1 独立阶段小输入而最终比较超限。
- 隔离 HTTP 检查 29 项、Agent HTTP/CLI/MCP 检查 8 项、启动器检查 6 项通过。运行使用临时 CG_DATA_DIR、本机模拟供应商，没有真实付费模型调用。
- 浏览器实际打开项目管理并完成项目改名，协作页新增入口与回收站可见。内置浏览器在原生确认框处失去响应，因此本轮未将段落删除、回收恢复、空白新建和讨论失败输入保留的完整点击链计为浏览器通过；相关后端行为有自动化测试，前端处理已实现。
- 本次浏览器在隔离项目实际切换 S0 自检与 S1 原材料模式，容量显示分别包含 9.51 KB / 19.02 KB 前序结果预留；没有发起模型请求。此前受原生确认框限制的管理点击链仍不声明已通过。
- 分享包独立解压、逐文件 SHA-256、中文文件名 UTF-8 标志和敏感文件排除另行核验；本轮没有重新执行解压包 npm ci/build，不能套用旧包构建结论。

## 使用位置与限制

文稿项目管理：左上项目选择器或“更多 → 项目管理与回收站”。段落删除：正文“编辑”后，每段下方“删除段落”。协作记录管理：/agents 页头“新建协作”，下方“协作记录与角色输出”及“协作回收站”。

回收站是可恢复的移出使用列表，完整记录仍保存在本机 JSON，不执行永久删除，也不会压缩数据文件。模型结果超过 9 KB 或发生供应商故障时，已发请求仍可能计费；本次修订防止的是可预见的后续输入超限，不承诺所有调用成功。真实模型兼容性与效果尚未验证。
