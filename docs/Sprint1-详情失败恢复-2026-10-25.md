# Sprint 1：详情失败可见与恢复

范围：仅解决主工作台详情加载失败后空白、缺少重试，以及同链路的错误关闭和操作禁用。未修改接口、存储、CSS、CLI 或历史缓存；未更新分享包、GitHub 或 3210 服务。

## 交付行为

- 详情请求独立记录 loading / error / ready，并绑定项目 ID 和更新时间；切换项目取消旧请求，过期响应不能写回。
- 首次详情失败时主区保留项目标题，显示可读错误、重试按钮和骨架；慢响应显示加载提示和骨架。
- 已有详情刷新失败时保留正文与本机草稿，显示同一套错误与重试面板。重试成功后恢复完整操作。
- 详情错误与工作区轮询错误互不覆盖，304 不清除已有轮询错误；两个工作台的横幅关闭键清理实际显示的错误来源。详情错误保留在重试面板中，避免关闭后再次无提示。
- 操作 busy 与详情就绪分开。缺少完整输入时暂停开始、保存、采纳、恢复版本、材料提交、讨论发送及导出；项目管理、切换、设置与帮助保持可用。停止已知运行不依赖详情重新就绪。

本次冗余清理限于该链路：移除旧的全局 busy 合并，统一复用详情反馈 JSX；没有混入全局 CSS 合并、类型统一或组件拆分。

## 重复执行

不要在服务正在使用的正式目录执行 build。复制源码到独立目录，执行 `npm ci`、`npm run build` 后运行 `npm run test:detail`。脚本自动启动随机端口和临时数据，结束时停止自己启动的服务。

浏览器 QA 工具未加入生产依赖。环境须提供 Playwright 与 axe-core；也可指定：

```powershell
$env:CG_PLAYWRIGHT_MODULE = '外部工具目录\playwright\index.mjs'
$env:CG_AXE_SOURCE = '外部工具目录\axe-core\axe.min.js'
$env:CG_TEST_REPORT_DIR = '验收证据目录'
npm run test:detail
```

默认使用本机 Edge；其他已安装 Chromium 通道可通过 `CG_BROWSER_CHANNEL` 指定。真实模型、长期历史性能和其他平台不属于本轮验证。
