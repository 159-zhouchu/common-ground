# 共桌 Common Ground

让多个 AI 围绕同一份任务分工，让建议回到可检查、可追溯的工作流程。

共桌是一个运行在本机的单用户 AI 工作台，提供两条主要流程：

- **AI 协作**：将任务上下文交给规划、分析、审查和汇总角色，生成交给执行 Agent 的简报；也可带回实际改动与测试结果继续复核。
- **文稿审阅**：导入原稿与参考材料，查看带引用和差异的修改建议，由用户逐条决定是否采纳，并保留版本历史。

本地新增[定向审查与分项验收](docs/定向审查.md)：可针对整篇、选中段落或指定问题设定验收项，分别查看通过、需修改和证据不足，并单独复查其中一项。

当前版本：`0.1.0`，处于早期阶段。项目使用 Next.js、React、TypeScript 与本地 JSON 存储，无需单独安装数据库。

2026-10-25 本地复核修正了供应商响应限流、无效 JSON 请求、讨论幂等重放和协作轮询；清理确认失效的样式。处理依据及验证范围见 [全面复核记录](docs/全面复核-2026-10-25.md)。

## 功能概览

| 功能            | 当前实现                                                               |
| --------------- | ---------------------------------------------------------------------- |
| AI 协作中转台   | 规划 → 分析与审查并行 → 汇总；支持上下文粘贴、简报复制与 Markdown 下载 |
| 文稿审阅        | 分段编辑、问题建议、材料引用、逐条接受／拒绝／暂缓                     |
| 检查策略        | 快速检查（S0）、多角度分析（S1）、核对材料（S5）                       |
| 模型连接        | 自定义 API 地址、协议、模型 ID、密钥和价格；每次运行显式分配连接       |
| 版本与导出      | 保存修订历史，导出 Markdown 或 DOCX                                    |
| 数据管理        | 项目重命名、项目与协作记录回收及恢复                                   |
| 可选 Agent 入口 | 命令行和 STDIO MCP；不自动注册或修改客户端配置                         |

## 快速开始

### 环境要求

- Node.js **22.9.0 或更高版本**，以及随 Node.js 安装的 npm。
- 首次安装需要联网下载依赖。
- 真实模型调用需要自行配置 API 连接；网页聊天会员不能代替 API 密钥。

当前验证环境为 **Windows、Node.js 24.21.0**。Linux/macOS 提供命令行入口，但尚未完成原生系统实测。

### Windows 双击启动

1. 下载并解压项目源码，保留 `package-lock.json`。
2. 双击根目录的 `启动共桌.cmd`。
3. 首次启动会检查 Node.js 版本，并在缺少依赖或构建时安装、构建。
4. 浏览器打开 <http://127.0.0.1:3210>。

关闭网页不会停止服务。使用 `停止共桌.cmd` 停止由启动器启动的实例。

### 使用终端

在项目根目录依次运行：

```sh
npm ci
npm run build
node scripts/start.mjs
```

打开 <http://127.0.0.1:3210>。停止服务：

```sh
node scripts/stop.mjs
```

开发模式使用：

```sh
npm ci
npm run dev
```

也可在构建后运行 `npm start`，以前台模式预览。`npm run dev` 和 `npm start` 用 `Ctrl+C` 停止；默认都使用 3210 端口，请勿同时启动。

### 更新已有安装

先用旧版停止脚本停止服务，再备份私有数据、更新源码，并重新运行 `npm ci` 和 `npm run build`。双击脚本不会仅凭源码发生变化就自动重新构建。

## 使用 AI 协作

访问 <http://127.0.0.1:3210/agents>。

1. 在“模型连接”中保存需要的 API 配置。
2. 点击“复制任务整理指令”，交给正在工作的执行 AI。
3. 将返回的 JSON 粘贴到“AI 上下文包”，检查需要共享的内容。
4. 为四个角色分配连接，确认预算后开始协作。
5. 将生成的执行简报复制给执行 AI，由其审查、实施和验证。
6. 需要复核时，将实际 diff、测试结果和遗留问题作为 `review` 阶段上下文再提交。

| 角色        | 职责                     |
| ----------- | ------------------------ |
| planner     | 拆解目标与任务步骤       |
| analyst     | 分析实现方式             |
| reviewer    | 审查风险与验证需求       |
| synthesizer | 汇总观点、分歧和执行建议 |

默认流程通过人工复制转交文本；自动化发生在共桌内部的模型调度与汇总环节。共桌本身不会启动编码 Agent、修改外部项目，或替用户批准操作。

每个协作任务最多四次模型请求，不自动重试。四个角色可以复用同一连接，但不能据此认定为独立验证。只有 `succeeded` 且 `ready` 表示取得完整顾问简报，**不表示任务已执行、内容正确或测试通过**。

命令行和 MCP 接入见 [AI 协作与 Agent 接入](docs/Agent接入.md)。

## 使用文稿审阅

访问 <http://127.0.0.1:3210>。

1. 创建项目，粘贴原稿或导入 UTF-8 TXT／Markdown。
2. 添加 TXT、Markdown 或 DOCX 参考材料，设置目标和约束。
3. 选择检查策略并分配模型连接。
4. 核对建议中的原文、差异和材料引用，逐条接受、拒绝或暂缓。
5. 保存新版本，按需要导出 Markdown 或 DOCX。

| 策略          | 用途                     | 模型请求数 |
| ------------- | ------------------------ | ---------- |
| S0 快速检查   | 单连接检查，可选追加自检 | 1 或 2     |
| S1 多角度分析 | 两路提案后比较汇总       | 3          |
| S5 核对材料   | 初审后复核               | 2          |

采纳建议前，服务端核对成果版本、来源版本及原文片段。编辑、采纳和恢复旧稿均创建新版本。DOCX 导入只提取文本，不保留原文件的分页、批注、图片与版式。

内置**合成示例预览**展示预置问题，不请求模型、不产生模型费用；它不代表真实策略差异或准确率。示例切换为真实运行后仍可能计费。

## 模型连接与费用

配置入口：<http://127.0.0.1:3210/connections>。

- 支持 OpenAI Responses API 和 Chat Completions 兼容接口；供应商兼容性仍需逐个验证。
- 默认最多保存 10 个连接，全进程最多同时发送 2 个模型请求。
- 保存、读取配置不会调用模型。明确点击连接测试、开始运行或发送讨论时才会发出模型请求。
- 连接测试发送一次小请求，可能计费；测试通过不代表模型质量合格。
- 运行开始时固定连接与配置快照；不会在失败后静默更换供应商。
- 配置了价格且供应商返回用量时才能计算费用，否则显示未知。费用预留和任务预算不能替代供应商账户硬限额。
- 失败、超时、取消或中断的请求仍可能已经计费；项目不自动重试付费请求。

## 数据与隐私

默认数据目录为项目根目录的 `.data/`：

| 文件                    | 内容                             |
| ----------------------- | -------------------------------- |
| `workspace.json`        | 项目、材料、文稿、版本与调用记录 |
| `connections.json`      | 模型连接配置及 API 密钥          |
| `agent-jobs.json`       | 协作上下文、输出、费用与运行状态 |
| `connection-tests.json` | 最近的连接测试状态与用量记录     |

**API 密钥在本机文件中明文保存，没有应用级加密。** 页面配置接口不回传已保存密钥，但本机文件仍需依靠操作系统权限保护。

真实调用会将所需上下文发送给用户配置的 API 供应商。使用前应检查材料内容和供应商的数据政策；不要提交无权共享的内容。

- 服务默认仅监听 `127.0.0.1`，执行本机 Host／Origin 校验。
- 本项目没有公网账户认证、租户隔离与多人权限，不适合直接改成公网服务。
- 不要上传或分享 `.data/`、真实 `.env`、密钥、私人上下文与日志。
- 在服务停止后备份整个数据目录。回收站保留记录，并不会缩小数据文件。
- 服务重启后，未完成任务会标为中断，不自动续跑或重发模型请求。

启动器支持通过进程环境变量 `CG_DATA_DIR` 指定数据目录、通过 `CG_PORT` 指定端口。自定义启动与停止时应使用相同配置；固定端口的 npm 开发命令和 Windows 浏览器打开地址不会自动随之变更。

## 容量与已知限制

- 最多 50 个使用中的项目；每个项目最多 20 份材料、100 段正文。
- 单份参考文件不超过 5 MiB，提取文本不超过 50,000 字符。DOCX 另限累计解压 20 MiB（包括图片等资源）、1000 个 ZIP 条目及 8 秒解析时限，每个服务进程最多同时解析 2 份；不保证所有小于 5 MiB 的复杂文件均能导入。导入成功不代表全部材料能同时交给模型。
- 单次模型输入清单上限为 100,000 UTF-8 字节，另有协议封装。文稿多步初始请求上限为 80,000 字节，Agent 初始目标／阶段／上下文合计上限为 70,000 字节。
- 每步结构化输出最多 9,000 字节；超限显式失败，不截断，已发送请求可能计费。
- 使用单进程 JSON 存储；历史积累后文件和写入成本会增长，不支持多进程共享同一数据目录。
- 尚未实现 PDF／OCR、外部检索、全面语义依赖发现、多人实时协作或跨服务重启续跑。
- 尚未验证所有真实供应商、付费模型效果和实际成本收益；模型意见仍需人工或执行方验证。

输入限制的集中定义见 [lib/limits.ts](lib/limits.ts)。


## 目录结构

```text
app/                 页面、API 路由与样式
  agents/            AI 协作中转台
  connections/       模型连接页面
  workbench/         文稿抽屉与共用展示组件
lib/                 调度、模型协议、存储与业务逻辑
scripts/             启动、停止、CLI 与 MCP 入口
tests/               自动测试与本机模拟供应商
docs/                使用说明、实现契约及验证记录
public/              可选静态资源目录，空目录可能不包含在源码包中
.data/               私有运行数据，不进入公开仓库
```

`node_modules/` 是安装依赖，`.next/` 是构建产物，均不作为源码发布内容。`package-lock.json` 应保留，以便复现依赖版本。
